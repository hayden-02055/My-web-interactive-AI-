## 2. Design Decisions

### DD-35 · 모바일 셸은 FAB → 전체 화면 오버레이

PRD §14가 제시한 세 후보(bottom sheet · floating chat · full-screen overlay) 중 **floating 진입 버튼 + 전체 화면 오버레이** 조합을 채택한다.

**근거**

결정 기준은 **콘텐츠 높이의 예측 불가능성**이다. 하나의 어시스턴트 메시지는 다음을 세로로 쌓는다.

```text
X-ray 파이프라인 5슬롯   (펼침 시)
답변 텍스트
MVP outline 블록          (Goal · Pipeline · Scope · Case Study · Caveats)
제안 카드 N개
```

| 후보 | 판정 |
|---|---|
| **전체 화면 오버레이** | ✅ 데스크톱 패널과 동등한 세로 예산 → SDD-05·06·07 컴포넌트를 **반응형 변형 없이 재사용** |
| Bottom sheet | ❌ 부분 높이에서 X-ray가 압축되고 중첩 스크롤 발생. 드래그 제스처 상태 관리 추가 |
| 상시 분할 | ❌ 모바일 세로 공간상 양쪽 모두 사용 불가 수준 |

FAB를 쓰는 이유는 **닫힌 상태에서 포트폴리오를 가리지 않기 위해서**다. 상시 노출 입력창은 화면 하단을 영구 점유하며, PRD §16의 "사용자의 모든 행동을 Agent가 제어하는 UI"에 가까워진다.

> 실제 모바일 렌더 확인 결과가 이 판단과 다르면 본 결정을 개정한다. 특히 MVP outline 블록이 예상보다 짧게 나온다면 bottom sheet가 재검토 대상이 된다.

### DD-36 · 오버레이 닫기는 언마운트가 아니다

오버레이를 닫아도 `AgentProvider`와 대화 상태는 유지된다. 표시 여부만 전환한다.

**근거**

> FR-02 — Agent는 사이트 전체에서 Persistent 상태를 유지해야 한다.

언마운트하면 대화가 사라진다. `sessionStorage` 복원으로 되살릴 수는 있으나, 스트리밍 중 닫기·재열기에서 진행 중 요청이 끊긴다.

**구현 제약**

- `AgentProvider`는 오버레이 바깥, 트리 상단에 마운트한다
- 오버레이는 표시 전환만 담당하는 셸이다
- 닫힌 상태에서도 스트리밍이 계속되며, FAB에 진행 표시를 노출한다

### DD-37 · 숨겨진 포트폴리오의 page context는 마지막 값을 유지한다

오버레이가 열려 포트폴리오가 보이지 않는 동안, page context 스토어는 **직전 관측값을 보존**한다. `null`로 되돌리지 않는다.

**근거**

이건 함정이다. 포트폴리오를 `display: none`으로 숨기면 `IntersectionObserver`가 교차 없음을 보고하고, 순진한 구현은 컨텍스트를 `null`로 만든다. 그러면 **Case Study를 보다가 Agent를 열어 "why did you build this?"라고 묻는 핵심 시나리오가 정확히 실패한다.**

PRD §9.1이 예시로 든 바로 그 흐름이다.

**정책**

- 관측 대상이 사라져도 마지막 유효값을 유지
- 오버레이를 닫고 스크롤을 재개하면 정상 갱신
- 전송 시점 스냅샷 규칙(SDD-04 DD-20)은 그대로 적용

### DD-38 · 접근성은 "차단 요소 제거"까지를 MVP 범위로 한다

전면 최적화가 아니라, **키보드만으로 모든 P0 기능에 도달 가능**한 상태를 목표로 한다.

**MVP 범위**

| # | 항목 |
|---|---|
| A-01 | 모든 상호작용 요소가 Tab 순회에 포함되고 포커스가 보인다 |
| A-02 | 오버레이 열림 시 포커스 트랩, ESC로 닫힘, 닫으면 FAB로 포커스 복귀 |
| A-03 | 제안 카드 · X-ray 토글 · 시작 프롬프트가 Enter/Space로 동작 |
| A-04 | 제안 클릭 후 대상 섹션으로 포커스 이동 (SDD-05 DD-28 재확인) |
| A-05 | 스트리밍 텍스트가 `aria-live="polite"` (SDD-04 U-06 재확인) |
| A-06 | 섹션 내비게이션 건너뛰기 링크 |
| A-07 | 이미지 대체 텍스트, 헤딩 레벨 순서 |

**P1로 미루는 것**

스크린리더 낭독 최적화, X-ray 상태 변화의 상세 announce, 색 대비 전면 감사.

**근거**

> PRD §14 — Agent와 Portfolio 모두 keyboard navigation을 **고려한다.**

"고려"는 전면 준수가 아니다. 다만 **키보드로 도달 불가능한 기능이 있으면 그건 고려가 아니라 결함**이므로, 그 선까지는 MVP에 포함한다.

### DD-39 · INV-01 검증을 자동화 테스트로 고정한다

"백엔드 없이 포트폴리오가 동작한다"를 수동 확인이 아니라 **E2E 테스트로 고정**한다.

**근거**

INV-01은 이 제품의 최상위 불변식이고, 매 SDD의 DoD에 반복 등장했다. 그런데 지금까지는 사람이 확인했다. 앞으로 콘텐츠 추가·리팩터링이 계속될 텐데, 사람이 매번 확인하지 않으면 **조용히 깨진다.**

`API_BASE_URL`을 도달 불가 주소로 지정한 상태에서 전 섹션 탐색·Contact 도달·콘솔 오류 없음을 검사하는 테스트를 CI에 추가한다.

### DD-40 · 성능은 예산으로 판정한다

초기 로딩 예산을 정하고 측정한다. 예산을 충족하면 최적화하지 않는다.

**예산**

| 항목 | 기준 |
|---|---|
| 포트폴리오 first contentful paint | 예산 내 |
| Agent 번들이 초기 렌더를 차단하지 않음 | 필수 |
| Lighthouse Performance | 목표치 설정 후 측정 |

**근거**

> PRD §14 — Agent가 있더라도 기본 Portfolio의 초기 로딩을 크게 방해하지 않아야 한다.
> PRD §5.1 — Is this necessary, or merely nice to have?

예산 미달일 때만 지연 로딩·코드 분할을 도입한다. 측정 없이 최적화부터 하는 것은 이 프로젝트의 원칙에 어긋난다.

측정값과 판정을 §7에 기입한다.

## 3. Mobile Shell

### 3.1 구성

```text
web/src/components/agent/mobile/
├── AgentFab.tsx          # 진입 버튼 · 스트리밍 진행 표시
└── AgentOverlay.tsx      # 전체 화면 셸
```

`AgentProvider`와 패널 내부 컴포넌트는 재사용한다. **SDD-04 U-07의 상태·셸 분리가 여기서 회수된다.**

### 3.2 요구사항

| # | 요구 |
|---|---|
| M-01 | 데스크톱 브레이크포인트에서는 FAB·오버레이 미렌더, 기존 2컬럼 유지 |
| M-02 | 모바일에서 포트폴리오는 SDD-01과 동일한 단일 컬럼 |
| M-03 | FAB는 콘텐츠 가독성을 해치지 않는 위치에 고정 |
| M-04 | 오버레이 열림 시 배경 스크롤 잠금, 닫으면 원래 스크롤 위치 복귀 |
| M-05 | 오버레이는 안전 영역(노치·홈 인디케이터)을 존중 |
| M-06 | 가상 키보드 노출 시 입력창이 가려지지 않음 |
| M-07 | 닫힌 상태에서도 스트리밍 유지, FAB에 진행 표시 (DD-36) |
| M-08 | 브레이크포인트 전환 시 대화 상태 유지 |

**M-06은 실기기 확인이 필요하다.** 뷰포트 높이 처리 방식(`dvh` 계열)은 브라우저별 차이가 있어 데스크톱 에뮬레이션으로는 재현되지 않는다.

**M-08의 이유**: 태블릿 회전이나 브라우저 창 크기 변경 시 셸이 교체되는데, 상태가 셸 안에 있으면 대화가 사라진다. DD-36과 같은 제약이다.

| C-10 | 스크롤 리렌더 프로파일링 | SDD-04 미검증 | ✅ 확인 완료 — 41회 스크롤 스텝 중 nav DOM 변경 5회(실제 섹션 전환 수와 일치), 리렌더 폭증 없음(DD-21) |
| C-11 | X-ray `failed` 상태 렌더 확인 | SDD-05·06·07 미검증 | ✅ 확인 완료 — "Failed" 라벨 + "✕" 글리프로 구분 렌더 |

**C-05가 권장 최상위인 이유**

모델이 tool을 우회해 텍스트로 링크를 쓰면 **제안 카드와 X-ray가 그 상호작용을 놓친다.** 화면은 안 깨지지만 PRD §17의 핵심 퍼널 지표(`Agent → Case Study navigation CTR`)가 구조적으로 누락된다. FR-05의 실질 충족도도 떨어진다.

프롬프트에서 "포트폴리오 내부 위치를 안내할 때는 반드시 `suggest_section`을 사용하고, 답변 본문에 내부 링크를 작성하지 않는다"를 명시하는 것으로 대응했다(SDD-03 `app/agent/prompts.py` 개정). 마크다운 링크·tool 이름 언급은 실측으로 사라진 것을 확인했으나, 모델이 여전히 tool을 호출하지 않고 "확인해 보세요" 식으로 말로만 안내하는 경우가 남아있어 **완전히 해결되지 않았다.** 더 강한 모델로 교체하거나 few-shot 예시를 프롬프트에 추가하는 것이 다음 시도 후보 — Post-MVP로 이월.
